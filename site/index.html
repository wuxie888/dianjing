03 / THE DIANJING PROCESS

四步，
不是套模板。

点击每一步，查看点睛在自己的真实仓库里怎样判断、采用和验收。

点睛自身仓库 · 当前事实

先确认它真的是什么。

  • 公开仓库，默认分支为 main
  • MIT License，已接入 Validate Actions
  • GitHub Pages 已启用，当前没有版本化 Tag 或 Release

稳定输入 · 稳定目标 · 成功标准

一句话先说清产品合同。

  • 输入：已经完成或接近发布的真实代码仓库
  • 动作：核验、定位、构成、验收
  • 输出：别人看得懂、装得上、愿意相信的公开产品页

按产品价值选择，而不是堆模块

点睛自己采用了三个表面。

  • 仓库底座：README、安装、许可证与公开边界
  • 动态表达：GitHub 兼容 Hero 与减少动态回退
  • 展示网站：用真实网页证明视觉、动效和交互能力

每一种“完成”分开报告

本地、远端、Pages 和 Release 不是一回事。

  • README 分别检查桌面端与窄屏阅读顺序
  • Pages 检查响应式、交互和减少动态
  • 没有 Tag 或 Release，就明确写成尚未发布版本
