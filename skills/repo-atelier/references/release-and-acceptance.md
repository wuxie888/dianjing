# 发布与公开产物验收

## 证据状态

始终分开：

1. 本地文件已经修改
2. 本地测试和视觉验收通过
3. 远端分支已经更新
4. Tag 已创建并可见
5. GitHub Release 已发布
6. Social Preview 已上传并在外部展开
7. Pages 已部署并可公开访问
8. 安装链路在干净环境通过
9. 用户完成第一次真实任务
10. 官方目录或商店已审核

前一项不能自动证明后一项。

## 本地发布前

- 仓库审计脚本通过或所有警告已有解释
- Git diff 只包含本次授权范围
- README 和文档链接有效
- Logo、截图、GIF、视频已逐项检查
- Pages 已执行响应式、深浅模式和减少动态验收
- 安装、升级、卸载命令已核验
- 版本、清单、CHANGELOG 和 Release Notes 一致
- LICENSE 与包元数据一致
- 没有密钥、Cookie、私有链接、本机路径或未授权素材
- 工作区已有用户修改未被覆盖

## 远端发布

只有用户授权后执行：

- 推送稳定源码
- 创建 Tag
- 创建带说明的 Release
- 上传或设置 Social Preview
- 启用或部署 Pages
- 修改仓库 About、Topics、Homepage 或 Settings

记录每项操作的真实结果，不把命令退出成功写成页面已经对用户可见。

## 公开产物回归

从公开 Tag 或仓库重新开始：

1. 使用全新目录检出。
2. 核对 Tag SHA 和 Release。
3. 打开公开仓库首页，检查 README 首屏和媒体。
4. 打开所有关键相对链接。
5. 检查 Social Preview 实际展开效果。
6. 检查 Pages 生产 URL、404、控制台、响应式和减少动态。
7. 按公开说明完成一次安装。
8. 完成第一次真实任务。
9. 测试升级路径，不把重复安装当成升级。
10. 报告未验证项和证据强度。

## 验收语言

推荐：

- “本地 README 和 Pages 已实现并通过本地浏览器验收”
- “远端 `main` 已推送，公开仓库可以看到新 README”
- “公开 Tag 全新检出后的静态检查通过”
- “用户报告跨设备安装通过；未保留录屏和设备版本”

避免：

- “已经发布完成”，但没有说明远端、Tag、Release 或 Pages
- “用户都会安装”，只有作者机器测试
- “Social Preview 已生效”，只把图片提交进仓库
- “动画完全兼容”，没有测试移动端和减少动态
- “官方插件”，实际只是第三方 Git 市场

## 失败分级

| 失败 | 处理 |
| --- | --- |
| 文案或链接错误 | 最小修复并重新检查 |
| 媒体加载或格式失败 | 转码、压缩或提供静态兜底 |
| Pages 构建失败 | 保留构建日志，修复后重新部署 |
| 减少动态不可用 | 阻止 L3/L4 验收通过 |
| 安装链路失败 | 不宣称产品可安装 |
| 远端状态不可见 | 区分推送成功与用户可见 |
| 用户已有改动冲突 | 停止覆盖，说明冲突并请求方向 |
